# Noonoo — Accessibility

Noonoo **owns the accessibility tree** and **borrows the protocol**. The tree is
a projection of the DOM, computed style, and layout into the model assistive
technology consumes; the platform machinery (AccessKit, AT-SPI, UiKit, WinRT) is
a separate, opt-in integration. That split is the same one used for GPU
rasterization and windowing: the engine pays nothing for a backend it is not
using, and the backend cannot silently turn accessibility into a no-op.

The old engine's Linux path was a no-op that consumers had to re-enable. Noonoo's
tree is on by default (`noonoo-shell`'s `a11y` feature is a default feature), and
the bridge is the only opt-in part.

## The boundary

| Owned (`crates/noonoo-a11y`) | Borrowed (`integrations/noonoo-accesskit`) |
| --- | --- |
| Roles, names, descriptions, values, states | AccessKit's protocol types |
| Heading levels, bounds, tree composition | AT-SPI/UiKit/WinRT adapters (host backend) |
| Hidden/presentational rules | Platform event delivery |

The engine's lockfile stays free of AccessKit. The integration has its own
lockfile and is excluded from the workspace.

## The model

One [`A11yNode`](../crates/noonoo-a11y/src/node.rs):

| Field | Meaning |
| --- | --- |
| `id` | Tree-wide identity, unique within one built/composed tree |
| `node` | The source `noonoo_dom::NodeId` (diagnostic; per-document) |
| `role` | What the node is (see below) |
| `name` | The computed accessible name |
| `description` | The computed accessible description |
| `value` | Current value, for controls that have one |
| `level` | Heading level, for headings |
| `states` | Disabled, focused, selected, required, read-only, busy, expanded, checked |
| `bounds` | Layout rectangle in page coordinates, when laid out |
| `children` | Exposed children, in document order |

`A11yTree` carries the root and the focused node's `id`. Build it with
`build` (no layout, no bounds) or `build_in` (bounds from a `LayoutTree`, plus a
focused node).

## Roles

`Role` is Noonoo's own compact vocabulary — not AccessKit's, and not ARIA's full
set. It covers documents, landmarks (`Navigation`, `Main`, `Banner`,
`ContentInfo`, `Complementary`, `Region`, `Search`), structure (`Heading`,
`Paragraph`, `StaticText`, `List`/`ListItem`, `Table`/`TableRow`/`TableCell`,
`RowGroup`, `ColumnHeader`/`RowHeader`, `Figure`/`Caption`), controls (`Button`,
`Link`, `Image`, `TextBox`, `CheckBox`, `RadioButton`, `Slider`, `SpinButton`,
`ComboBox`, `ListBox`/`ListBoxOption`, `Switch`), and containers (`Generic`,
`Group`, `Legend`, `Label`, `Dialog`, `Alert`, `Status`, `ProgressBar`,
`Separator`, `LineBreak`, `TabList`/`Tab`/`TabPanel`, `Toolbar`, `Menu`/
`MenuItem`).

Mapping rules:

1. An explicit `role=` wins when Noonoo models it.
2. Otherwise the tag decides (`h1`–`h6` → heading, `a[href]` → link, `input` by
   `type`, `ul`/`ol` → list, `nav` → navigation, ...).
3. An unknown `role=` falls back to the tag, never to "hide it".
4. `role="none"` / `role="presentation"` make the element *presentational*: it
   contributes no node, and its children are promoted.

## Names

The accessible name is computed in this order, stopping at the first non-empty
result:

1. `aria-labelledby` — the text of each referenced element, joined.
2. `aria-label`.
3. Host-language naming: `<img alt>`, `<area alt>`, an `<input type=image alt>`,
   an input button's `value` (with `Submit`/`Reset` defaults), and a `<label>`
   associated by `for=` or by ancestry.
4. Name from contents, for roles where that is correct (button, link, heading,
   list item, table cell, header cell, option, tab, menu item, label, caption,
   legend).
5. `title`.

Text is whitespace-collapsed. A generic container does **not** take a name from
its contents; its text is exposed as `StaticText` children instead, so the name
and the text are not duplicated.

The description follows `aria-describedby`, then `title` (when it was not used
as the name), then `placeholder` for text fields.

## Values and states

Values come from `aria-valuetext`, `value`/`aria-valuenow`, a textarea's text, or
a select's selected option. States come from the host attributes and their ARIA
equivalents:

- `disabled` / `aria-disabled`
- `required` / `aria-required`
- `readonly` / `aria-readonly`
- `aria-busy`, `aria-selected`/`selected`, `aria-expanded`
- `aria-checked` (`true`/`false`/`mixed`); a checkbox/radio/switch without it is
  explicitly `false`, not "not applicable"
- `focused` from the node passed to `build_in` (or `Host::a11y`)

## What is hidden, what is promoted

**Absent with the whole subtree:**

- `display: none`
- `[hidden]`
- `aria-hidden="true"`
- non-rendered tags: `head`, `title`, `meta`, `link`, `base`, `script`, `style`,
  `template`, `noscript`, `param`, `source`, `track`
- `<input type="hidden">`

**Presentational — no node, children promoted:**

- `role="none"` / `role="presentation"`
- `<img alt="">` without an overriding label/role
- `visibility: hidden` / `collapse`

`visibility` is inherited, so text under a hidden ancestor stays out; a
descendant that sets `visibility: visible` (its computed value differs) is
exposed again. This mirrors the CSS cascade rather than flattening the subtree.

## Bounds and composition

With a layout pass, bounds are the union of every box a source node produced
(wrapped text has several), in page coordinates.

`Host::a11y` builds one tree per layer, offsets each by the layer's rectangle
minus its scroll, and composes them under a single `Role::Window` root. Node ids
are renumbered so they are unique across the window; the focused node, if any,
is reported in `A11yTree::focus`. In a composed tree use `id` as the identity;
`node` is per-document diagnostic data.

## The bridge

`integrations/noonoo-accesskit` exposes one function:

```rust
pub fn tree_update(tree: &A11yTree) -> accesskit::TreeUpdate
```

It projects every node (role, label, description, value, level, bounds, flags,
toggled state, children) and sets the update's focus. A window backend calls it
whenever the tree changes and hands the result to the platform adapter. The
adapter is not linked into the engine.

## Observing it

```sh
noonoo --a11y page.html     # parse → style → layout → accessibility JSON
```

The JSON is deterministic: `{"root": …, "focus": …}`, with `id`, `role`, `name`,
`description`, `value`, `level`, `node`, `bounds`, `states`, and `children` in a
fixed order. It is the headless artifact tests assert against.
